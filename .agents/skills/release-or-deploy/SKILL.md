# リリース・デプロイする

> **このスキルはまだこのプロジェクト用に記入されていません。**
> 初めてデプロイの形が決まったら、実際に成功した手順をここに書き写してください。
> **記入前に、このファイルの手順を実行したことにしないでください。**
> 実際のコマンドが分からない場合は、推測で実行せずユーザーに確認してください。

## Overview

対象環境、リリース単位、切り戻し方法をここに書きます。

## Parameters

- **environment** (required): `staging` / `production` など。
- **version** (optional): リリースバージョン、タグ、コミット SHA。
- **rollback_target** (optional): 戻す先のバージョン。

## Prerequisites

- 必要な権限、環境変数、外部サービスへのアクセスがある。
- `ai-docs/OPERATIONS.md` が現在の運用と一致している。
- `ai-docs/TESTING.md` の必要な確認が完了している。

## Steps

### 1. リリース対象を確認する

```bash
git status
git log --oneline -n 10
```

**Constraints:**

- MUST 未コミットの変更が混ざっていないことを確認する。
- MUST どのコミットが出るのかをユーザーに示してから進める。

### 2. 品質確認を実行する

`ai-docs/TESTING.md` のコマンドを実行する。

**Constraints:**

- MUST 確認が落ちた状態でデプロイしない。
- MUST 実行できなかった確認があれば、デプロイ前に報告する。

### 3. デプロイする

```bash
# 未設定 — 実際のデプロイコマンドをここに書く
```

**Constraints:**

- MUST 本番への反映は、明示的に依頼された場合だけ実行する。検証環境のつもりで本番に出さない。
- MUST 破壊的な操作（DB マイグレーション、データ削除）を含む場合は、実行前にユーザーへ確認する。

### 4. デプロイ後に確認する

- 主要画面が開ける。
- 主要操作が動く。
- エラーログに重大な異常がない。
- 外部連携が動く。

**Constraints:**

- MUST 実際に確認する。デプロイコマンドが成功したことを「動作確認」と呼ばない。

### 5. 記録する

手順や環境が変わったら、このファイルと `ai-docs/OPERATIONS.md` を更新する。

## Verification

- 対象環境で意図したバージョンが動いている。
- 主要機能のスモークテストが完了している。
- 切り戻し先が分かっている。

## Rollback / Recovery

| 方法 | 手順 | 注意 |
|---|---|---|
| 前バージョンへ戻す | 未設定 | 未設定 |
| 設定を戻す | 未設定 | 未設定 |
| DB を復旧する | 未設定 | 高リスク。バックアップ確認必須 |

**Constraints:**

- MUST 切り戻し手順が未設定のまま、切り戻しが必要な操作をしない。
